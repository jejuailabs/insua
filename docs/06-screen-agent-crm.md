## 2. 좌측 세로 레일 (`SideRail`)

| 순서 | 아이콘(lucide)  | i18n 키            | 경로                      |
| ---- | --------------- | ------------------ | ------------------------- |
| 1    | `Home`          | `nav.home`         | `/[locale]/crm/dashboard` |
| 2    | `Users`         | `nav.crm`          | `/[locale]/crm` ★기본     |
| 3    | `FileText`      | `nav.interactions` | `/[locale]/interactions`  |
| 4    | `CalendarCheck` | `nav.schedule`     | `/[locale]/schedule`      |
| 5    | `Mail`          | `nav.messages`     | `/[locale]/messages`      |
| 6    | `BarChart3`     | `nav.stats`        | `/[locale]/stats`         |
| 7    | `Settings`      | `nav.settings`     | `/[locale]/settings`      |

- 폭 64px (모바일/태블릿), 1024px↑에서 200px로 확장하며 라벨을 아이콘 우측에 배치.
- 활성 항목: `--accent-soft` 배경 + `--accent` 아이콘·라벨 + 좌측 3px 인디케이터 바.
- 아이콘 22px, 라벨 `micro`(11/600), 아이콘 아래 4px.

## 3. 상단 액션 바

5개 정사각 타일. 각각 `--surface-2` 배경, `--radius-inner`, 아이콘 20px + 라벨 11/600.

| 액션      | 동작                                                          | 이번 범위                                                                            |
| --------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 검색      | 이름·업체명·전화·태그 통합 검색 시트                          | ✅ 구현                                                                              |
| 지도 보기 | 고객 주소를 지오코딩해 지도에 핀으로 표시                     | ✅ 구현 (`PinMap`, OSM 타일 — 카카오맵 SDK 로 교체 예정)                             |
| 상담 녹음 | 녹음 → Storage 저장 → **곧바로 STT** → 구조화 텍스트까지      | ✅ 구현. **`consent.recording === true` 인 고객만** 대상에 오른다                    |
| 신규 등록 | 고객카드 생성 폼                                              | ✅ 구현                                                                              |
| 캘린더    | 연락 예정일(`nextContactDueAt`) 월간 뷰                       | ✅ 구현                                                                              |

`단체 문자` 는 폭 100% 버튼. 누르면 선택 모드로 전환되어 카드마다 체크박스가 나타난다.
**실제 SMS 발송은 이번 범위 밖** — 대상자 목록과 문안을 만들어 클립보드 복사 / CSV 내려받기까지만.
(발송 대행사 연동은 별도 계약이 필요하고 미확정이다.)

## 4. 필터 · 정렬

- 칩: `전체 128` / `A등급 28` / `B등급 56` / `C등급 44` — 숫자는 실데이터 카운트.
  S등급이 존재하면 칩을 하나 더 추가한다(이미지에는 A/B/C만 있으나 데이터 모델은 S를 지원).
- 활성 칩: `--accent-soft` 배경 + `--accent` 텍스트 + 1px `--accent` 테두리.
- 정렬 드롭다운: `연락 임박순`(기본) / `최근 등록순` / `이름순` / `등급순`.
  **기본값이 "연락 임박순"인 게 핵심이다.** 이 화면의 목적은 "누구에게 연락할 차례인가"를 알려주는 것이다.

## 5. 고객카드 (`PersonCard`)

`docs/04` §5.3 의 컴포넌트. 데이터 매핑:

| 화면 요소     | 필드                         | 비고                                       |
| ------------- | ---------------------------- | ------------------------------------------ |
| 사진          | `contact.photoURL`           | 없으면 이니셜 아바타 (배경 `--surface-2`)  |
| 이름          | `contact.name`               | subtitle 16/600                            |
| 등급 배지     | `contact.tier`               | `TierBadge`                                |
| 업체명        | `contact.company`            | body 15/400                                |
| 직위          | `contact.position`           | caption muted                              |
| 전화          | `contact.phone`              | 아이콘 + 번호. 탭하면 `tel:`               |
| 웹사이트      | `contact.website`            | 아이콘 + 도메인만 표시                     |
| SNS           | `contact.socials`            | 있는 것만 아이콘 노출 (인스타/카톡/네이버) |
| 특이사항      | `contact.note`               | 우측 컬럼. 라벨 `crm.note` + 값 2줄 말줄임 |
| 상담로그 버튼 | → `/interactions?contactId=` | outline, 등급색                            |

카드 테두리 색 = 등급색. 다크 모드에서는 `box-shadow: 0 0 12px {tier}22` 를 추가해
이미지의 발광 느낌을 살린다. 라이트 모드에서는 글로우 없이 1px 테두리만.

### 연락 임박 표시

`nextContactDueAt` 이 오늘 이전이면 카드 좌상단에 작은 점(`--danger`)과
`{n}일 지남` 캡션을 붙인다. 이미지에는 없지만 등급별 연락 주기 기능(제안서 5.1)의
가시적 산출물이 반드시 필요하다. 없으면 등급이 그냥 장식이 된다.

## 5.5 고객카드 수정·삭제 (사용자 확정 사양) ✅ 구현됨

카드의 [수정]을 누르면 이름·업체·직위·전화·등급·**주소**·특이사항·동의 3종을 고친다.

- 권한: 소유 설계사 또는 관리자. 서버 액션이 `ownerAgentId` 를 직접 대조한다.
- **주소가 바뀌면 좌표 캐시(lat/lng)를 지운다** — 옛 좌표는 거짓말이 되므로 다음 조회 때 다시 찍는다.
- 삭제는 같은 모달 안에서 확인을 한 번 더 받는다. 지울 때:
  - 하위 `interactions`(상담로그)까지 배치로 함께 삭제. 문서만 지우면 로그가 고아로 남는다.
  - 이 고객으로 만든 공개 매장이 있으면 **비공개(`isPublic:false, status:'hidden'`)로 내린다.**
    근거가 사라진 랜딩이 검색에 계속 뜨면 안 된다.

## 5.6 상담 녹음 (사용자 확정 사양) ✅ 구현됨

- 헤더 [상담 녹음] → 동의 고객 선택 → 마이크 녹음(경과시간 표시) → 종료.
- **파일 저장이 먼저, STT 가 나중이다.** 정리에 실패해도 녹음 원본은 남는다 —
  상담 내용은 다시 만들 수 없다. 실패 시 상담로그에서 [텍스트로 정리]로 재시도.
- 상담로그 화면의 녹음 버튼도 같은 흐름(저장 → 자동 정리)을 탄다.
- 마이크 권한 거부·미지원이면 그 사실을 안내한다(조용히 실패하지 않는다).

## 6. 신규 등록 폼

최소 필수는 **이름 하나**. 나머지는 전부 선택. 입력 장벽을 낮추는 게 이 제품의 원칙이다.

```
이름*            [                    ]
사진             [ 촬영 / 갤러리 ]
업체명           [                    ]
직위             [                    ]
전화             [                    ]
등급             ( S )( A )( B )( C )     ← 기본 B
연락 주기        [ 등급 기본값 사용 ▾ ]     ← S:3일 A:7일 B:14일 C:30일
특이사항         [                    ]
─────────────────────────────────────
동의 항목
□ 정보 공유 동의  (플랫폼 공개 영역 노출)
□ 사진 공개 동의
□ 상담 녹음 동의
```

**동의 체크박스 3개는 기본 해제.** 미리 체크해두지 않는다.
`dataSharing` 이 꺼져 있으면 이 고객의 매장 정보는 소비자 피드에 절대 뜨지 않는다.

## 7. 상담로그 화면 (`/interactions`)

- 좌측: 고객 목록(축소형), 우측: 선택된 고객의 타임라인. 모바일에선 단일 컬럼.
- 타임라인 항목: 타입 아이콘 + 날짜 + 본문 + (있으면) AI 요약 뱃지 + 첨부.
- 입력: 하단 컴포저(`docs/04` §5.6과 같은 컴포넌트 재사용) — 텍스트 / 사진 / 음성 / 파일.
- AI 요약은 `docs/10` 어댑터. **이번 범위에서는 버튼만 두고 "준비 중" 상태로 둔다.**

## 8. 통계 화면 (`/stats`)

이미지에 상세가 없으므로 최소 구성으로 시작한다. 확장은 나중에.

- 등급별 고객 수 도넛
- 이번 달 접촉 횟수 (타입별 막대)
- 연락 지연 고객 수
- 내가 만든 매장 페이지 수 / 게시물 수

## 9. 빈 상태

| 상황          | 문구(ko)                       | 액션                 |
| ------------- | ------------------------------ | -------------------- |
| 고객 0명      | 아직 등록된 고객이 없습니다    | `첫 고객 등록하기`   |
| 필터 결과 0건 | 이 조건에 맞는 고객이 없습니다 | `필터 초기화`        |
| 상담로그 0건  | 첫 기록을 남겨보세요           | 컴포저로 포커스 이동 |

## 10. 데이터 접근 규칙 (재확인)

- `contacts` 는 `ownerAgentId == uid` 인 것만 읽힌다. 다른 설계사의 고객은 **존재조차 보이지 않는다.**
- 이건 제안서 10장의 "데이터 소유권 경계" 리스크에 대한 기술적 답이다. Security Rules로 강제한다.
- 관리자도 기본 화면에서는 남의 고객 목록을 열람하지 않는다. 열람이 필요하면 어드민 콘솔에서
  **감사 로그를 남기며** 접근한다 (`docs/09`).
