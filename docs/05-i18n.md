# 05. 다국어 (i18n)

## 1. 지원 언어

| 코드 | 언어       | 상태                             |
| ---- | ---------- | -------------------------------- |
| `ko` | 한국어     | **기본. 완역 필수**              |
| `en` | English    | 완역                             |
| `zh` | 中文(简体) | 슬롯 확보. 초기엔 `ko` 폴백 허용 |
| `ja` | 日本語     | 슬롯 확보. 초기엔 `ko` 폴백 허용 |

> **미확정**: 제주 인바운드 관광객 대상이라면 `zh`/`ja` 가 `en` 보다 우선일 수 있다.
> 우선순위는 사용자에게 확인이 필요하다. 구조는 4개 다 넣고, 번역 완성도만 단계적으로 채운다.

## 2. 라우팅

`next-intl` 의 locale prefix 방식. `/ko/crm`, `/en/feed` 처럼 항상 prefix를 붙인다
(`as-needed` 를 쓰면 기본 언어 URL과 나머지가 비대칭이 되어 공유 링크가 헷갈린다).

```ts
// src/lib/i18n/routing.ts
import { defineRouting } from 'next-intl/routing'

export const routing = defineRouting({
  locales: ['ko', 'en', 'zh', 'ja'],
  defaultLocale: 'ko',
  localePrefix: 'always',
  localeDetection: true, // Accept-Language 기반 최초 1회 감지
})
```

미들웨어는 `docs/03` §5 에서 인증 가드와 합쳐 하나로 구성한다.

로그인 사용자의 `users.locale` 이 URL locale과 다르면, **URL을 우선**하되
설정 화면에서 언어를 바꿀 때만 `users.locale` 을 갱신하고 해당 locale로 라우팅한다.
(로그인할 때마다 사용자가 보고 있던 페이지 언어를 강제로 바꾸면 혼란스럽다.)

## 4. 사용 규칙

```tsx
// 서버 컴포넌트
import { getTranslations } from 'next-intl/server'
const t = await getTranslations('crm')
<h1>{t('title')}</h1>

// 클라이언트 컴포넌트
'use client'
import { useTranslations } from 'next-intl'
const t = useTranslations('crm')
<span>{t('filterAll', { count: 128 })}</span>
```

**금지 사항**

- JSX 안에 한국어 리터럴 직접 작성 금지
- 문장을 조각내서 이어붙이기 금지 (`t('you') + name + t('hasNewMessage')`).
  → 반드시 `t('greeting', { name })` 처럼 플레이스홀더 하나로.
- 복수형은 ICU 문법으로: `"items": "{count, plural, other {#개}}"`.
  한국어는 복수형이 없지만 `en` 은 필요하므로 키 구조를 처음부터 ICU로 잡는다.

## 5. 숫자 · 날짜 · 통화

```ts
// src/lib/utils/format.ts
export function formatCurrency(amount: number, locale: string) {
  if (locale === 'ko') return `${amount.toLocaleString('ko-KR')}원`
  return new Intl.NumberFormat(locale, {
    style: 'currency',
    currency: 'KRW',
    maximumFractionDigits: 0,
  }).format(amount)
}
```

- 한국어에서만 `18,000원` 표기. 나머지 언어는 `₩18,000`.
- 상대 시간("10분 전")은 `Intl.RelativeTimeFormat` 사용. 직접 문자열 조합 금지.
- 영업시간 `08:00 - 20:30` 은 24시간 표기 고정 (locale별 12시간제 변환하지 않는다 — 매장 정보는 원문 유지).
- 부동산 금액 단위(만원)는 한국 고유 단위다. `en`/`zh`/`ja` 에서는
  `formatDeposit()` 이 원 단위로 환산해 표기한다. 이 로직을 컴포넌트에 흩뿌리지 말고 유틸 하나로.

## 6. 번역 누락 검사

```bash
pnpm i18n:check   # ko.json 키 집합 대비 나머지 파일의 누락/잉여 키를 출력
```

스크립트는 `scripts/check-i18n.mts` 에 있다 (`.mts` 인 이유: Node 의 타입 스트리핑으로 바로 실행하는데
확장자가 `.ts` 면 CommonJS 로 먼저 파싱을 시도해 경고가 난다). `pnpm build` 가 앞단에서 자동 실행한다.

**M1 구현 메모**: `ko` 를 베이스로 깔고 해당 언어를 그 위에 덮는 병합을 `lib/i18n/request.ts` 에서 한다.
이게 없으면 키 하나 빠질 때마다 `MISSING_MESSAGE` 로 화면이 깨진다. 폴백이 있어야 §1의
"zh/ja 는 슬롯만 확보" 전략이 실제로 성립한다.

> ⚠️ **zh / ja 번역은 원어민 검수를 받지 않았다.** 키 구조를 채우고 의미가 통하는 수준까지만 해놨다.
> 실서비스 노출 전에 검수가 필요하다. 특히 `anonymous.roomName`("아프니까 사장이다") 같은
> 관용 표현은 직역이 어색할 수 있다.

기존 스펙 그대로,
`ko` 기준 누락이 있으면 **경고만** 출력한다(빌드 실패시키지 않는다 — 초기엔 폴백이 정상 동작이므로).
단 `ko` 에 없는 키를 코드가 참조하면 **실패**시킨다.

## 7. 언어 전환 UI

- 위치: 설정 화면 + 소비자 앱 헤더(관광객 대상이므로 접근성 높게).
- 형태: 드롭다운. 각 언어를 **해당 언어로** 표기 (`한국어` / `English` / `中文` / `日本語`).
  "Korean"처럼 현재 언어로 번역해 표기하지 않는다.
- 전환 시 현재 경로를 유지한 채 locale만 교체 (`next-intl` 의 `Link`/`usePathname` 사용).

## 8. 사용자 생성 콘텐츠는 번역하지 않는다

매장 소개, 게시물 본문, 익명방 글, 메뉴 이름은 **원문 그대로** 노출한다.
자동 번역을 붙이는 것은 별도 결정 사항이며 이번 범위 밖이다.
UI 텍스트(라벨·버튼·안내문)만 다국어 대상이다.
