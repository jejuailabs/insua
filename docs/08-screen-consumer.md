# 08. 소비자 화면 — LOCAL HERO

> 근거 이미지: `docs/assets/ref-04-consumer-localhero.png` (4개 테마 — 앰버/브라운/퍼플/그린)

## 1. 컨셉

소비자 화면의 주인공은 **가게가 아니라 사람**이다.
`김순자 사장`, `박민수 바리스타`, `이지은 디자이너`, `김철수 농부` — 이미지가 전부
직함과 이름을 앞세우고 있다. 상호명이 아니라 사람 이름이 카드 제목이다.

이게 이 제품이 다른 로컬 앱과 다른 지점이고(제안서 2.2 — 익명 거래가 아닌 신뢰 기반),
화면 설계도 거기에 맞춘다. 카드 제목을 상호명으로 바꾸지 말 것.

## 4. 히어로 카드 (`HeroCarousel` 소비자 변형)

`docs/04` §5.1 과 같은 컴포넌트. 소비자 변형에서 달라지는 것:

| 요소        | 설계사/업주 화면   | 소비자 화면                                                 |
| ----------- | ------------------ | ----------------------------------------------------------- |
| 우상단 배지 | 등급 (`A등급`)     | **카테고리** (`🍽 음식점`, `☕ 카페`, `✂ 미용실`, `🌱 농부`) |
| 제목        | 상호명             | **사람 이름 + 직함** (`김순자 사장`)                        |
| 부제        | 업종 설명          | 대표 아이템 (`30년 전통 순두부찌개`)                        |
| 하단        | `자세히 보기` 버튼 | **정보 타일 3~4칸**                                         |

### 정보 타일 (카드 하단)

카테고리마다 다른 조합이 온다. 이미지에서 확인된 것:

| 카테고리 | 타일                                                                   |
| -------- | ---------------------------------------------------------------------- |
| 음식점   | `10% 할인` · `시그니처 순두부찌개` · `08:00-20:00`                     |
| 카페     | `10% 할인` · `시그니처 핸드드립` · `09:00-19:00` · `원두증정`          |
| 미용실   | `10% 첫방문 할인` · `시그니처 페이드컷` · `10:00-20:00` · `예약필수`   |
| 농부     | `10% 할인` · `오늘수확 신선보장` · `무료배송 내일도착` · `유기농 인증` |

타일은 `--surface-2` 반투명 배경 + 아이콘 + 2줄 텍스트(상단 강조, 하단 caption).
카테고리별 타일 구성은 `lib/consumer/heroTiles.ts` 에 매핑 테이블로 둔다. 하드코딩 분기 금지.

카테고리 배지 색: `--accent` 를 쓰되 카테고리별 색을 따로 두지 않는다.
(팔레트를 바꾸면 4장 이미지처럼 화면 전체 톤이 함께 바뀌는 게 의도)

## 5. 반경 필터

제안서 5.6의 핵심. 헤더 아래 또는 카드 상단에 칩으로 배치.

```
[ 1km ] [ 3km ] [ 5km ]        기본 3km
```

- 위치 권한 요청은 **첫 진입 시 자동으로 띄우지 않는다.** 반경 칩을 누를 때 요청한다.
  이유: 진입 즉시 권한 팝업이 뜨면 이탈률이 높다.
- 권한 거부 시: 지역 선택 드롭다운(제주시 / 서귀포시 / 읍면 단위)으로 폴백.
- 쿼리는 geohash 접두 매칭 + 클라이언트 거리 재계산. Firestore에 GeoPoint 반경 쿼리가 없기 때문이다.

## 6. 상품 그리드 (직거래)

- 3열 그리드(모바일), 4열(태블릿↑).
- 각 카드: 이미지(1:1) + 배지(BEST/NEW/SALE) + 하트(우상단) + 이름 + 부제 + 가격 + 장바구니 버튼.
- 가격은 `tabular-nums`. `19,800원`.
- **장바구니·결제는 이번 범위 밖.** 버튼을 누르면 `저장했습니다` 토스트 + 찜 목록에 추가되고,
  상세 화면에서 `전화 문의` / `카카오톡 문의` 로 연결한다. 결제 UI를 만들지 말 것.
- 섹션 제목도 카테고리별로 다르다: `오늘의 신선한 제주 직거래` / `갓 볶은 신선한 원두 & 디저트` /
  `헤어 & 두피 케어 제품` / `제주에서 바로 수확한 신선 먹거리`.
  → `consumer.productSection.{category}` 키로 관리.

## 7. 쿠폰

- 카드 정보 타일의 `10% 할인` 을 누르면 쿠폰 시트가 열린다.
- 발급 = `couponIssues` 문서 생성. 사용 = 매장에서 QR 또는 코드 확인 후 `usedAt` 기록.
- `costSharing` 은 저장만 하고 화면에 노출하지 않는다. 소비자가 알 필요 없는 내부 정보다.
- **정산·환급은 구현하지 않는다.**

## 8. 찜한가게

`users/{uid}/saved/{storeId}` 서브컬렉션. 하트 토글은 낙관적 업데이트(즉시 반영 후 실패 시 롤백).

## 9. 마이페이지

- 프로필(구글 계정 정보)
- 언어 선택 (`docs/05` §7)
- 화면 밝기 + 색상 테마 (`docs/04` §6)
- 담당 설계사 지정 — **이게 제품 수익구조와 연결된 지점이다.**
  설계사 코드 입력 또는 목록에서 선택 → `users.agentId` 설정 → 쿠폰 비용 분담 구조 변경.
  UI 문구는 혜택 중심으로: `담당 설계사를 지정하면 추가 혜택을 받을 수 있습니다.`
  **다만 지정이 무엇을 의미하는지(내 정보가 해당 설계사에게 전달됨) 명확히 고지하고 동의를 받는다.**
  이건 개인정보 이슈이므로 얼버무리면 안 된다.
- 로그아웃

## 10. 비로그인 상태

- 피드와 매장 페이지는 **읽기 가능**. 콜드스타트 완화를 위해 진입 장벽을 낮춘다.
- 찜, 쿠폰 발급, 문의는 로그인 유도 시트.
- 로그인 유도 문구: `이 가게를 저장하려면 로그인이 필요합니다` — 기능을 특정해서 말한다.
  `로그인이 필요합니다` 같은 일반 문구는 쓰지 않는다.
