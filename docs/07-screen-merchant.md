## A-2. 헤더

- 좌측: 햄버거 또는 홈 아이콘 + 서비스명. 이미지에 `소상공인 돌만의 공간` / `소상공인 돌만의 페이지`
  두 표기가 섞여 있다 → **`merchant.spaceName` 키 하나로 통일**하고 값은 정식 명칭 확정 시 교체.
  (현재 임시값: `소상공인들만의 공간`)
- 우측: 검색, 알림(읽지 않음 있으면 우상단 점 `--danger`).
- 인사말은 시간대별로 바꾼다: 오전 `좋은 아침이에요, 사장님` / 오후 `오늘도 수고 많으세요, 사장님` /
  저녁 `오늘도 고생하셨어요, 사장님`. (이미지 4번째 변형이 밤 인사 + 달 아이콘이었다)

## A-3. 퀵액션 6칸

| 아이콘           | 라벨          | 이동                   |

| `MessagesSquare` | 익명방        | `/anonymous`           |

## A-4. 익명방 카드 — 이 화면에서 유일하게 강조색을 통째로 쓰는 요소

- 배경: `--accent` (다크에서는 채도 높은 accent, 라이트에서는 accent 원색 유지 + 흰 텍스트)
- 안쪽 미리보기 리스트는 반투명 흰 배경 `rgba(255,255,255,.10)`.
- `지금 {n}명이 이야기 중` — 실시간 접속자 수. **실시간 카운트는 구현 부담이 크므로
  MVP에서는 "최근 24시간 작성자 수"로 대체하고 문구를 그에 맞게 쓴다.** 없는 숫자를 지어내지 말 것.
- 하단에 상시 고지: `anonymous.notice` — "업장명·주소·인물정보는 자동으로 가려집니다."

## A-5. 각 섹션 데이터

- 부동산 → `listings` where `status == 'active'` orderBy `createdAt desc` limit 6
- 정부지원 → `supportPrograms` where `status == 'active'` limit 5.
  **`sourceUrl` 이 없는 레코드는 렌더하지 않는다** (`docs/02` §7).
  섹션 하단에 `support.sourceNotice` 고지 상시 노출.
- AI Tools → 정적 3개 (`docs/10`)
- 공동구매 → `groupBuys` where `status == 'open'` orderBy `deadline asc` limit 3

## A-6. 하단 탭바 + 글쓰기 FAB

5칸: 홈 / 알림 / **글쓰기** / 내정보 / 더보기.
중앙 FAB(`--accent` 원형, 위로 8px 돌출)을 누르면 `ComposerSheet` 가 올라온다.

## A-7. 커뮤니티 게시판 (사용자 확정 사양) ✅ 구현됨

홈의 각 섹션 [더보기]와 퀵액션 6칸은 **전부 실제 화면으로 간다.** 아무 데도 안 가는
더보기는 만들지 않는다 — 누를 수 있게 생긴 것은 눌리는 것이다.

| 입구                          | 경로         | 내용                        |
| ----------------------------- | ------------ | --------------------------- |
| 부동산 매매·임대 더보기/퀵액션 | `/realty`    | 가게 자리 매물              |
| 정부지원 더보기/퀵액션         | `/support`   | 지원사업·특별대출 정보      |
| 공동구매 더보기/퀵액션         | `/groupbuy`  | 공동구매 모집               |
| 정보공유 퀵액션                | `/share`     | 장사 정보 공유              |
| AI Tools 더보기/퀵액션         | `/ai-tools`  | (기존)                      |
| 익명방 퀵액션                  | `/anonymous` | (기존)                      |
| 메인 직거래 더보기             | `/market`    | (기존)                      |

- 네 게시판은 목록+글쓰기라는 같은 골격이라 `boardPosts` 한 컬렉션을 `kind` 로 나눈다.
  화면도 `BoardPage`/`BoardScreen` 하나를 공유한다.
- **글쓰기 권한** — 소상공인·설계사·관리자. 소비자는 읽기만(이 공간은 사장님들의 자리).
- 필드: `title` · `meta`(금액·기한 한 줄) · `sourceUrl`(원문·신청 링크) · `body` · 사진.
  정부지원은 출처 링크가 신뢰의 근거라 항상 함께 보여준다.
- 홈 섹션은 **실글이 있으면 실글, 없으면 목데이터**로 빈 카드를 피한다.
- 어드민 콘텐츠 관리에 `게시판` 탭이 붙어 숨김/복원/삭제가 된다.

## B-2. 섹션 제목이 업종마다 다르다

이미지에서 관찰된 것: 음식점 `대표 메뉴`, 카페 `시그니처 메뉴`, 베이커리 `인기 메뉴`, 고깃집 `대표 메뉴`.

```ts
const MENU_SECTION_KEY: Record<StoreCategory, string> = {
  restaurant: 'merchant.representativeMenu',
  cafe: 'merchant.signatureMenu',
  bakery: 'merchant.popularMenu',
  salon: 'merchant.signatureService',
  farm: 'merchant.mainProduce',
  retail: 'merchant.popularItems',

```

업종에 따라 말이 달라지는 건 우연이 아니라 의도다. 하나로 통일하지 말 것.

## B-3. "모듈 수정"

우상단 버튼. 누르면 섹션 편집 모드로 전환된다.

- 각 섹션에 드래그 핸들과 표시/숨김 토글이 나타난다.
- 순서와 노출 여부를 `stores/{id}.modules` 배열로 저장:
  ```ts
  modules: { id: 'menu'|'about'|'map'|'coupon'|'products'|'notice', visible: boolean, order: number }[]
  ```
- 편집 모드는 **업주 화면에서만.** 공개 페이지에는 이 버튼이 없다.

## B-4. 공개 페이지 `/s/[storeId]`

**앱 화면이 아니라 검색·공유로 바로 들어오는 단독 랜딩페이지다** (사용자 확정 사양).
앱 레일이 없으므로 나갈 길과 목차를 페이지가 직접 준다.

- 비로그인 접근 가능. `store.isPublic === true` 이고 `status === 'published'` 일 때만.
- 서버 렌더 + ISR (`revalidate: 600`).
- **상단 바(`LandingNav`, sticky)** — 뒤로(히스토리 없으면 홈) · LOCAL HERO 로고(홈) ·
  섹션 목차(소개/메뉴/오시는 길/FAQ/후기) · 공유.
  검색결과에서 바로 들어온 방문자는 뒤로 갈 곳이 없다 — 그때 홈으로 보내는 게 이 버튼의 핵심이다.
- **레이아웃** (사용자 확정 사양) — PC 는 2컬럼: 왼쪽에 **세로 히어로 카드(4:5, sticky)**,
  오른쪽에 내용이 아래로 흐른다. 모바일은 카드 아래로 쌓인다. 컨테이너 `max-w-5xl`.
  히어로 카드는 어디서나 세로 비율을 유지한다 — 카드가 이 서비스의 기본 단위다.
- **섹션 흐름**(오른쪽 컬럼) — AI 헤드라인 → 한눈에 보기(칩) → 매장 소개(소제목+서술형 3섹션) →
  메뉴 → 오시는 길(큰 지도) → FAQ → 방문 후기 → AI 생성 고지.
- ⚠️ **고객 등급(S/A/B/C)은 노출 금지.** 설계사가 매긴 내부 평가라 공개 랜딩은 물론
  업주 본인 화면(`/store`)에도 표시하지 않고, **값 자체를 클라이언트로 내려보내지 않는다.**
  `Store.tier` 는 선택 필드이고, 업주 화면은 서버에서 제거한 뒤 전달한다.
  액션 바도 매장 객체 전체가 아니라 이름·전화·주소만 받는다.
- 메타데이터는 AI 카피(`store.seo`)를 우선 쓰고 없으면 매장 필드로 폴백한다:
  title/description/keywords/canonical/OG/Twitter (`docs/10 §7.2`).
- **JSON-LD** — `Restaurant`(또는 `LocalBusiness`) + `FAQPage` 를 `@graph` 하나로.
- 색인: `src/app/sitemap.ts` 가 공개 매장 × 4로케일 URL 을 싣고, `robots.ts` 가
  개인 화면(`/admin` `/crm` `/me` `/saved` …)을 막는다.
- 하단에 `ComposerSheet` 대신 `[전화하기] [길찾기] [공유]` 액션 바.
- **연결된 `contact.consent.portrait !== true` 면 사장님 사진을 쓰지 않고**
  매장 대표 이미지로 대체한다. 동의 없는 인물 사진 공개는 금지.

## B-5. 컴포저 → 게시물 생성 플로우

```
사진 선택
  → 클라이언트에서 EXIF 파싱 (GPS만 추출)
  → EXIF 제거 후 리사이즈(장변 1600px, webp)
  → Storage 업로드 stores/{storeId}/posts/{uuid}.webp
  → posts 문서 생성 { storeId, images:[url], location, locationSource:'exif' }
  → 매장 페이지 + 중앙 Live Feed에 동시 노출
```

- EXIF에 GPS가 없으면 `store.location` 으로 대체하고 `locationSource: 'store'`.
- 업로드 실패 시 재시도 버튼. 사진은 로컬에 유지해서 다시 고르게 하지 않는다.
- 음성 메모: 최대 3분, `audio/webm`. 재생 UI는 파형 없이 재생/일시정지 + 길이만.

## B-6. "익명방에 글쓰기"가 컴포저 안에 있는 이유

같은 입력창에서 실명(매장 소식)과 익명(고민)을 고를 수 있게 한 구조다.
익명을 선택하면 **입력창 테두리가 `--text-muted` 로 바뀌고 상단에 `익명으로 작성 중` 배지**가 뜬다.
실수로 실명 게시되는 일이 없도록 시각적 구분이 확실해야 한다. 전송 직전 확인 다이얼로그도 띄운다.
