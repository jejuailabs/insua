# 00. 제품 개요

> 출처: 사업제안서 「AI 로컬 비즈니스 플랫폼 — 보험설계사 CRM에서 시작하는 지역 운영체제」(2026.08)
> 이 문서는 개발 판단에 필요한 부분만 압축한 것이다. 사업적 논거 전문은 원본 제안서를 참조.

## 1. 한 줄 정의

설계사가 **평소 하던 일(방문·상담·사진)** 을 그대로 하면, 그 부산물이 자동으로
지역 콘텐츠와 상권 데이터로 바뀌는 플랫폼.

## 2. 데이터 플라이휠 (제품 설계의 뼈대)

```
① 관계관리   설계사가 고객 방문/상담         → 고객카드(관계 로그)
     ↓
② 콘텐츠화   사진 1장 → AI가 포스터/카드뉴스  → Live Feed 게시물
     ↓
③ 확산       외부 SNS 통합계정 자동발행       → 외부 도달 (※ 이번 범위 밖)
     ↓
④ 구조화     동의된 사업정보를 상권지도화     → 로컬 비즈니스 허브
     ↓
⑤ 거래화     쿠폰·직거래·주문                 → 로컬 커머스 매출
```

**개발 관점의 함의**: ①→② 전환(사진 한 장을 실제로 올리게 만드는 것)이 최대 마찰 지점.
그래서 입력 UI는 **카카오톡과 동일한 감각**이어야 한다(`docs/07` 하단 컴포저 시트).
이게 이 제품의 성패를 좌우한다고 원 제안서가 명시하고 있다.

## 3. 3-Sided 구조

| 역할          | 코드값     | 메인화면                    | 핵심 가치                 |
| ------------- | ---------- | --------------------------- | ------------------------- |
| 보험설계사    | `agent`    | CRM 고객카드 대시보드       | 관계관리 자동화           |
| 소상공인      | `merchant` | 커뮤니티 대시보드 + 내 매장 | 무료 홍보 + AI 툴 + 정보  |
| 소비자/관광객 | `consumer` | 반경 기반 로컬 피드         | 동네 소식 + 쿠폰 + 직거래 |
| 운영자        | `admin`    | 어드민 콘솔                 | 회원·콘텐츠·신고 관리     |

회원가입 직후 **역할을 하나 선택**하고, 이후 라우팅과 메인화면이 완전히 분기된다.
(→ `docs/03-auth-roles-admin.md`)

## 4. 이번 범위에 포함되는 핵심 기능

### 4.1 AI 고객카드 (설계사)

- 고객 1인 = 히어로카드 1장 (사진 중심)
- 등급(A/B/C)에 따른 연락 주기 자동 관리 + 알림
- 관계 로그: 텍스트 / 음성메모 / 첨부파일 축적
- 지도 보기, 단체 문자, 신규 등록, 캘린더

### 4.2 자동 랜딩페이지 = "내 매장"

- 고객카드에 입력된 기본정보(상호, 연락처, 주소, SNS)만으로 매장 페이지가 자동 구성
- **보여지는 화면(소비자용)** 과 **입력 인터페이스(업주용)** 를 분리
- 업주는 사진 업로드·공지 등록만으로 페이지가 실시간 갱신

### 4.3 Live Feed

- 사진 1장 올리면 매장 페이지 + 중앙 피드에 동시 게시
- 최신 등록순 기본 정렬
- 소비자 화면에서는 반경 1km / 3km / 5km 필터

### 4.4 소상공인 대시보드 4대 축

1. **익명 게시판** — "아프니까 사장이다". 업장명·주소·인물정보 비식별화, 내부 로그는 보존
2. **소상공인 지원정보** — 정부 지원사업·정책·대출 정보
3. **AI 툴모음** — 메뉴판 이미지, 주제파 만들기, 가상 스튜디오
4. **상가 임대·매매 정보** — 사진 업로드 시 EXIF 위치로 자동 등록

여기에 이미지 기준으로 **공동구매·제주 혜택** 이 하나 더 붙는다.

### 4.5 소비자 화면 (LOCAL HERO)

- 로컬 사업자를 "히어로"로 전면에 세운 카드 캐러셀
- 그 아래 직거래 상품 그리드 (감귤·당근 등)
- 쿠폰: 담당 설계사 유무에 따라 비용 분담 구조가 다름 (플래그로만 저장, 정산 미구현)

## 5. 이번 범위 밖 (원 제안서에는 있으나 지금은 안 함)

| 기능                              | 이유                                                         |
| --------------------------------- | ------------------------------------------------------------ |
| 배달독립 플랫폼 (수수료 7% 목표)  | 라이더·물류·자본이 필요한 별개 사업. 제안서도 Phase 5로 분리 |

| 한국어               | 코드 표기       | 설명                                     |

## 7. 리스크 (개발 중 항상 의식할 것)

- **개인정보** — 통화·상담 기록, 익명방 비식별화 수준. 동의 없는 저장 금지.
- **초상권** — 고객 사진을 매장 페이지·피드에 노출할 때 별도 동의 플래그 필요.
- **익명방 운영** — 로그는 남되 신고·제재 경로가 반드시 있어야 함.
- **데이터 소유권** — 설계사 개인 CRM 데이터와 플랫폼 공용 데이터의 경계.
  스키마에서 `visibility` 필드로 명시적으로 구분한다 (`docs/02`).
